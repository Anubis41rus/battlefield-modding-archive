# KIT-RESEARCH — модели, классы, оружие ботов (14.10.2026)

Цель: у каждого бота свой класс (Assault/Engineer/Support/Recon), своя модель и оружие, как выбирает fun-bots
(`Player:SelectUnlockAssets` + `SoldierEntity:ApplyCustomization`). Сейчас все боты — копия кита человека.
Формат: факт (проверено) / гипотеза (не проверено).

## Что делает fun-bots (локальная копия `mods\fun-bots\ext\Server\BotSpawner.lua`)
- Факт: `_SetKitAndAppearance` (стр. 1914): ищет `Gameplay/Kits/<US|RU><Assault|Engineer|Support|Recon>[_XP4…]`
  и `Persistence/Unlocks/Soldiers/Visual/MP/<Us|RU>/MP_<US|RU>_<Класс>_Appearance01`, зовёт
  `Player:SelectUnlockAssets(kit, {appearance}, unlocks)`.
- Факт: после спавна `soldier:ApplyCustomization(_GetCustomization(bot, kit))` (стр. 1557) — `CustomizeSoldierData` со списком
  `UnlockWeaponAndSlot` (слоты 0..7: основное, пистолет, гаджеты, граната, нож).
- Факт: сейчас у нас `Player:SelectUnlockAssets` — заглушка (лог «Player:SelectUnlockAssets заглушка»), а
  `ApplyCustomization` только запоминает данные в Lua-объекте. Движку ничего не уходит.

## Что делает движок (декомпиляция `re\selectunlock_decomp.txt`, скрипт `re\ghidra-proj-server\decomp_addrs.py`)
- Факт: `0x00E331B0` — `fb::ServerPlayer::onPlayerSelectedUnlockAssetsMessage(this=ServerPlayer, msg)` (по логевентам
  `02C57778`/`02C5778C` — строки «Too many specializations…», «Missing characterCustomizationAsset»).
  Поля сообщения: `+0x38` ассет кита (`CharacterCustomizationAsset`), `+0x3C` массив ассетов внешнего вида,
  `+0x40` массив прочих (специализации, лимит 0x25). Функция проверяет доступность через vtable игрока `+0x18`,
  пересобирает вектор набора игрока (`in_ECX[0x12E]`/`[0x12F]` = `+0x4B8`/`+0x4BC`) и зовёт `0x00E33040`
  (слоты оружия) → `applyCustomization` `0x00E322F0`.
- Факт: `0x00E33040` — разбор слотов оружия по китам (вызывает `applyCustomization`; у нас уже разобрано в
  `WEAPONS-RESEARCH.md`).
- Факт: сообщение сети — `NetworkPlayerSelectedUnlockAssetsMessage` (строка в `.rdata`, регистрация `0x02330FC1`).
- Гипотеза: вызвать `0x00E331B0` самим, подложив сообщение с нужными ассетами — самый «настоящий» путь (как делает
  клиент при выборе класса). Нужны ЖИВЫЕ указатели ассетов и сборка Frostbite-массивов (размер в `[ptr-4]`).
  RET функции не проверен.

## Что известно о данных игрока (живая память сервера, чтение `ReadProcessMemory`)
- Факт: у ботов, созданных до входа человека, `+0x4B8 == +0x4BC` (вектор пуст), встроенный буфер на `+0x4CC` (cap +0x40).
- Факт: у человека вектор из ОДНОГО элемента (лог моста «шаблон команды … элементов=1»).
- Факт: объект по `+0x480` человека (`F580BDC8`, адрес одинаков в прогонах 78/79) — НЕ ассет кита с именем:
  vtable `0x02500E38`, на `+0x48/+0x5C/+0x70` единицы (похоже на матрицу трансформа). Название «кит» для `+0x480`
  в наших заметках, по всей видимости, неверно; что это, не выяснено.
- Факт: строки `Gameplay/Kits/USAssault` и т.п. в памяти сервера есть (`07EA7B32`, `0DFA95C0`), но прямых 4-байтовых
  указателей на начало этих строк (выровненных) нет. Поле имени у инстанса, видимо, устроено иначе (хеш/смещение).
  Значит «найти ассет по имени сканом строки» в лоб не работает.

## Живая память сервера (снято `ReadProcessMemory` с работающего сервера, человек в мире, 14.10 02:19)
- Факт: у ассета (`UnlockAssetBase`/`Asset`) `+0x00` vtable, `+0x04` флаги/счётчик, **`+0x08` указатель на полное имя**
  (строка лежит сразу за объектом), `+0x14` указатель на короткое имя, `+0x18` хеш имени.
  Пример: `F4840E10` → `Weapons/AKS74u/U_AKS74u`, хеш `E5BF98FE`; `F45AE590` → `…/MP/RU/MP_RU_Engi_Appearance01`.
- Факт: у человека (команда РФ, Инженер): `+0x480` → `F580BDC8` = **`Characters/Soldiers/MpSoldier`** (blueprint солдата, а НЕ кит —
  название «кит» в прежних заметках неверно); вектор `+0x4B8` = ОДИН элемент — внешний вид `MP_RU_Engi_Appearance01`;
  слоты оружия `+0x50C`, 10 штук по 0x24, в слоте 0 `Weapons/AKS74u/U_AKS74u`, в слоте 1 `Weapons/MP443/U_MP443`.
- Факт: **ассеты китов и оружия живые в памяти и находятся по имени**: строка имени → указатель на неё в `+0x08` объекта
  (объект = адрес ссылки − 8). Найдены: `Gameplay/Kits/USAssault` `F58F0E74`, `RUAssault` `F55513B4`, `USRecon` `F555CD24`,
  `RUEngineer` `F55E86A4`, `Weapons/M416/U_M416` `F48AE0F0`. Адреса одинаковы между прогонами (детерминированная куча).
  Прежний скан не находил их, потому что обрывался на 0x7FFE0000 (объекты выше 2 ГБ, сервер LARGE_ADDRESS_AWARE).
- Факт: ассеты внешнего вида (`MP_US_Assault_Appearance01`) как отдельные живые объекты по имени НЕ найдены (только
  строки в образе); у человека экземпляр появляется на время выбора. Гипотеза: достижимы по графу от кита
  (`VisualTable → CustomizationTable → UnlockParts → SelectableUnlocks`), у объекта кита `+0x18..+0x5C` — вложенные
  объекты таблиц (имена `ID_M_SOLDIER_PRIMARY`, `ID_M_SOLDIER_GADGET1`…). Не пройдено.

## Следующие шаги (по порядку)
1. Снять с живого человека (в мире) вектор `+0x4B8` и элемент: что за объект, как лежит имя (`Name`) в инстансе.
2. Найти в движке таблицу «GUID/хеш имени → инстанс» (поиск по партициям EBX) и вызвать её из моста — это и будет
   настоящий `ResourceManager:SearchForDataContainer` по живым объектам (сейчас — офлайн-индекс).
3. Реализовать `Player:SelectUnlockAssets(kit, {appearance}, unlocks)` в мосте: положить ассеты в вектор `+0x4B8`
   (движковый resize, как для оружия) и вызвать `applyCustomization` при спавне.
4. `ApplyCustomization(CustomizeSoldierData)` → слоты оружия `+0x50C` (формат уже известен, `WEAPONS-RESEARCH.md`).

## Не делать
- Не копировать `+0x4AC` (слабая ссылка игрока на себя) — давало «Самоубийство».
