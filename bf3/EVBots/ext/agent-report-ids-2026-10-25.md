# Отчёт: номера игроков клиент ≠ сервер (25.10.2026, только чтение)

## 1. Откуда берутся id (ФАКТ, файл:строка)
- Сервер мода: Lua-счётчик `local nextId = 1` — `evbots-dll\src\VextPlayerManager.cpp:147`; `PlayerManager:CreatePlayer`
  (стр. 1345–1380) берёт `id = nextId; nextId++` (1349–1350), `NewPlayer(id,…)` (1123, поле `id = id`), `playersById[id]` (1352).
  Счётчик только растёт (в `DeletePlayer` id не переиспользуется, стр. 1392) — при смене ботов уходит за 20–33.
  Людей мост тоже заводит через `CreatePlayer` (стр. 2754), т.е. и у человека id мода — счётчик, а не движка.
- Движковый игрок создаётся ОТДЕЛЬНО: `NativeBridge.CreateEnginePlayer` -> нативная `createPlayer` VA 0x00E644B0
  (`kNativeCreatePlayerRva` стр. 4277). Вызов: `createFn(mgr, nullptr, r1, r2, r3)`, где `r2 = -1` («движок выдаёт сам»)
  — стр. 4660–4664 и 4962–4965. id движка в Lua не возвращается и нигде не читается.
- Клиент: `Player.id` = `[игрок+0x3EC]` — `VextClientPlayers.cpp:33` (`kPlId`), чтение в `ReadInfo` (стр. 131), `l_clp_ids` (178),
  поиск по id — `PlayerById` (52–66, массив `pm+0xC0` по id). Источник — разбор VU (`ext\CLIENT-SLOTS-2026-10-23.md` ★★★, MODLOG стр. ~478).
  fun-bots клиента шлёт в `RaycastResults` именно этот id (`VextClient.cpp:125–156`), сервер ищет по своему (`VextNetEvents.cpp:170–178`).

## 2. Есть ли id в движке сервера (ФАКТ + ГИПОТЕЗА)
- ФАКТ: у ServerPlayer id хранится в `+0x3B8` (`re\vu\FIELDS-REPORT.md:13`: «VU отдаёт как Player.id, 0x10B995DD»).
  Подтверждено Ghidra (`bf3_server_Final.exe`): конструктор ServerPlayer `0x00E350B0` пишет `param_1[0xEE] = param_3` (=+0x3B8)
  и байт `+0x3BC = param_4` (isAI). Вызывает его `0x00E644B0(this=pm, a2=name?, a3=id, a4=isAI)`: в нём `a3 == 0xFFFFFFFF` ->
  `id = FUN_004C72F0()` (наименьший свободный бит битовой маски `pm+0xBC`); иначе id берётся как задан, проверяется
  «Player ID already taken in player manager!» (бит в `pm+0xBC`) и `id < [pm+8]` (число слотов); запись в `[pm+0xAC + id*4]`.
- Заметка: на сервере `+0x3EC` — совсем другое (`m_isIngame`, `kOffPlayerInGame`, стр. 8503). Клиентский `+0x3EC` и серверный
  `+0x3B8` — разные классы, смещения не сравнивать.
- ГИПОТЕЗА (не проверено): клиент получает тот же id по сети (создание игрока реплицируется с id сервера, `+0x3EC` клиента
  = `+0x3B8` сервера). Косвенно: на клиенте в прогоне 230 id были 20–33 — это похоже на слоты движка, а не на счётчик с 1.
  Прямо НЕ проверено: конструктор клиентского Player не разбирал (Ghidra клиента не открывал, мало вызовов).
- ФАКТ про текущее поведение: мод видит id от счётчика Lua, движок даёт ботам свои (наименьший свободный бит) — совпадать
  они не обязаны, что и наблюдали (12 из 12 мимо).

## 3. Предложение «как VU» (один id) — рекомендую (а), в два шага
Шаг 0 (проверка, дёшево, до правки): в прогоне логировать для каждого бота `Lua id`, `u32[ptr+0x3B8]` (сервер) и клиентский
`__clp_info` id по имени. Если серверный +0x3B8 == клиентский — гипотеза верна, дальше (а). Если нет — (б).

(а) id мода = id движка сервера:
 1. Добавить в мост (C++, рядом с `l_bridge_create_engine_player`, ~4649–4830 и 4946–5000) функцию чтения
    `NativeBridge.EngineId(ptr)` = `*(u32*)(ptr+0x3B8)` под SEH (проверить Readable).
 2. Ранние боты (CreateEnginePlayer вернул ptr сразу, VextPlayerManager.cpp:1363–1368): после `p.nativePtr = ptr` взять
    `eid = NativeBridge.EngineId(ptr)` и сделать `playersById[p.id]=nil; p.id=eid; playersById[eid]=p`.
 3. Поздние боты (ptr приходит позже через `PollCreatedBots`, стр. 1752–1764): там же в цикле перенумеровать. Проблема: до
    этого момента мод уже получил временный id (fun-bots хранит бота по объекту/имени, но если кладёт `player.id` в таблицы —
    разъедется). Надёжнее вариант (а'):
 (а') ВЫДАВАТЬ id сами и передавать движку: заменить `r2 = -1` (стр. 4660 и 4962) на id, выбранный в Lua. Движок принимает
    явный id (проверка занятости по `pm+0xBC`, предел `[pm+8]`). Тогда id мода известен сразу и совпадёт с движком. Выбор id —
    наименьший свободный, как делает движок (`FUN_004C72F0`): читать маску `pm+0xBC` (слов `[pm+0xC0..]`: размер `0x10` слов
    у `param_1+0x10` в аллокаторе — в Ghidra уточнить, это ГИПОТЕЗА) или считать по `[pm+0xAC+i*4] != 0`. Убрать счётчик
    `nextId` (стр. 147, 1349–1350) для ботов; для людей — id уже в движке (`+0x3B8` игрока, найденного по `RealPlayerName`).
 4. Люди: после правки у человека в моде тоже брать `+0x3B8` (сейчас счётчик, стр. 2754).
(б) запасной: сервер шлёт клиенту имя->id по службной посылке рядом с `__ev_bots` (`VextNetEvents.cpp:244–282`, приём
    `VextClient.cpp:203–225`), клиент в `countRaycastResults`/отправке `RaycastResults` подменяет `Bot1/Bot2` на серверные id.
    Минус: Lua клиента fun-bots шлёт свои id в разных местах (Mode 0/1/…), подмена — костыль, расхождение с VU (В19 останется).
