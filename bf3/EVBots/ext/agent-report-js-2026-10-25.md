# Отчёт: ошибка JS `querySelector` в меню fun-bots (25.10.2026)

Только чтение. Ничего не правилось, мод не трогался.

## Где в исходнике (проверено по тексту)
Папка страницы: `BF-Portable\Battlefield_3_Server\Instance\Admin\Mods\fun-bots\WebUI\` (исходники, vite-проект; `classes\BotEditor.js`).
Собранного `assets\index-C8K0XP01.js` в папке нет — в `assets\` только картинки и svg, поэтому номер строки из лога (`1`, минифицированный бандл) к исходнику не привязать. Соответствие сделано по тексту.

Главный кандидат — `classes\BotEditor.js`, `bindKeyboardEvents()`, обработчик `keydown` на `document.body`, ветка `IDK_Enter` (keyCode 13):
```
let form = getClosest(event.target, "ui-view");
let submit = form.querySelector('[data-action="submit"]');
```
`getClosest` (`classes\Utils.js`) возвращает `undefined`, если у цели нет предка `ui-view`. Проверки на `undefined` нет, поэтому `form.querySelector` падает с ровно той ошибкой из лога.

Второй участок того же вида: `BotEditor.js` около строки 539 (`getClosest(event.target, "ui-view").querySelector('[data-type="form"]')`) — в ветке клика по `submit*`. Для ошибки из лога менее вероятен, т.к. нужен клик вне `ui-view`.

## Вывод (факт / гипотеза)
- Факт: ошибка возникает в коде страницы, в ветке Enter, когда цель `keydown` находится вне `ui-view`. Код страницы без защиты.
- Факт: цель `keydown` равна `document.body`, когда ни один элемент не в фокусе. У нас окно WebView2 — дочернее окно игры (`VextWebUi.cpp`, ~368–390), клавиатура идёт через Win32 к оверлею; фокуса на поле ввода нет.
- Гипотеза (не проверено): это ошибка самой страницы, и на VU она тоже проявилась бы, если VU шлёт `keydown` с целью вне `ui-view`. Факт, на который опирается гипотеза: что Gameface доставляет `keydown` с целью внутри активного view, в нашем логе не проверено.
- Гипотеза (не проверено): отличие от VU может быть в фокусе. У нас фокус остаётся на body, а в Gameface, возможно, на элементе активного view. Проверяется сравнением `event.target` в VU-прогоне или в лог-выводе из страницы (не сделано).
- Не отличие: размер окна и порядок событий (`Client:UpdateInput`) к этой ошибке, по логу, не связаны; это только фон.

## Что сделать (для решения пользователя, без правок сейчас)
1. Подтвердить клавишу: добавить в шим лог `event.target.tagName` в `keydown` или снять прогон с отметкой нажатия Enter. Это нужно для проверки гипотезы.
2. Если подтвердится Enter с целью body: это ошибка страницы; у нас безопасный обход — либо оставить (меню от этого не ломается, пишется только WARN), либо добавить в шим защиту. Править мод fun-bots нельзя, поэтому обход только в нашем шиме (`VextWebUi.cpp`), после согласия.
3. Записать в `ext\VU-DIVERGENCES.md` только после проверки отличия от VU.

- Собранный бандл `index-C8K0XP01.js` не найден локально — точная строка в минифицированном коде не сверялась.
