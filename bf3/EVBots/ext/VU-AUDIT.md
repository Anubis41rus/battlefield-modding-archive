# VU-AUDIT — как VU (veniceext.dll) отдаёт данные моду и где мы отличаемся

> Начато 15.10.2026 (сборки 132–135). Правило: «как в VU» проверяем по коду VU, а не по догадкам.
> Логика ботов — Lua-мод fun-bots, код у нас и в VU один и тот же. Отличаться может только то,
> что VEXT отдаёт моду (свойства, методы, события). Поэтому аудит идёт по биндингам VEXT.

## 2. Инструменты (`C:\Games\re\vu\`, только чтение)

- `strref.py <имя> …` — где код `veniceext.dll` ссылается на строку (имя свойства/метода).
- `dis.py <VA> [n] [назад]` — дизассемблер Capstone по адресу.
- `bindings.py` → `bindings.txt` — карта биндингов SOL3 «имя → функция» (453 штуки) по шаблону
  `mov [ebp-0x20], ФУНКЦИЯ … mov [ebp-0x3C], ИМЯ … call регистратор`. Так зарегистрирован, например, `Player`.
- `pairs.py <от> <до>` — имена из таблиц на стеке (так зарегистрирован `SoldierEntity`; адреса функций там
  передаются иначе, через шаблоны SOL3, — пока не вытащены).

## 3. Факты из кода VU (проверено дизассемблером)

| Биндинг VU | Реализация в `veniceext.dll` | Смысл |
|---|---|---|
| `Player.soldier` | `0x1098C960`: `eax = [player+0x3C4]; if 0 → nil` | солдат = тело в движке; нет тела — `nil` |
| `Player.hasSoldier` | `0x1098D540`: `[player+0x3C4] != 0` | то же условие |
| `Player.alive` | `0x1098BC90`: вызов функции движка из таблицы VU `[0x18E74FC0]` | движковый `isAlive`, не флаг |
| `Player.corpse` | `0x1098C900` | не разобрано |
| `Player.CreateSoldier` / `SpawnSoldierAt` | `0x1098B5D0` / `0x10990700` | не разобрано |
| `SoldierEntity.*` (`pose`, `pendingPose`, `SetPose`, `isAlive`, `worldTransform`, …) | имена в `0x109BCF22…0x109BD12F` | адреса функций ещё не найдены |

Смещение `+0x3C4` у VU совпадает с нашим `kOffPlayerSoldier` — это подтверждает и наш разбор движка.

## 4а. Переключатели и тесты (сборка 136)

- В VU переключателей нет — всё «рабочее» включено. У нас обязательные теперь включены по умолчанию:
  `LEGACYEXT_INPUT_NATIVE`, `LEGACYEXT_SQUAD_HOOK`, `LEGACYEXT_SPM_CUSTOM`, `LEGACYEXT_PTS_REG` (явное `=0` выключает).
  Остальные флаги — откат конкретной правки или опыты, по умолчанию «как в VU».
- Тесты `input`, `mstart`, `move` удалены: они вмешивались в игру (переставляли пробного бота, жали газ).
  Новые пассивные проверки: `walk-start`/`walk-all`, `vu-soldier` (солдат ⇔ тело в движке), `vu-weapons`
  (мод видит слот и патроны), `vu-suicide` (самоубийства «за неверный путь» `GameDirector.lua:217`).

## 5. Другие факты прогонов 132–134 (для контекста)

- Раунд стартует только после захода живого клиента (сервер 00:38:31, клиент 00:39:11, раунд 00:40:08); до этого
  тел у ботов нет («солдат не готов» — 66 раз).
- Лучи работают (300–470 чистых результатов за ~22 с), в мод доходят. Версия «лучи сломались» не подтвердилась.
- Стакания при спавне нет (ближайшая пара 3.5–6.8 м).
- Перезарядки в движке нет: мост подменяет магазин через 2–4 с пустоты (`AMMO_FIX`).
- Попаданий по солдатам (по HP) мало: 8 за ~5 минут боя в 133. Причина не найдена.
