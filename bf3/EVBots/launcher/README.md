Одно окно для стенда Battlefield 3 в локальной сети: поднять сервер (с ботами), зайти в игру,
вести аккаунты, видеть серверы этого ПК и серверы друзей в LAN. Интернет не нужен и не используется.

Старый WinForms-проект `src\Legacy.Launcher` оставлен без изменений. Его README перенесён в
`C:\Games\trash\2026-10-13\launcher-README-2026-10-10.md`.

## Сборка

Нужен .NET 10 SDK (на машине стоит 10.0.401) и WPF (входит в Desktop Runtime). NuGet не используется.

```powershell
dotnet build C:\Games\Legacy\launcher\src\LegacyLauncher.Gui\LegacyLauncher.Gui.csproj -c Release
```

Результат: `C:\Games\Legacy\launcher\src\LegacyLauncher.Gui\bin\Release\net10.0-windows\LegacyLauncher.exe`
(x86, как и весь код проекта: bf3.exe 32-битный).

Проверки ядра (без запуска игры, сервера и бэкенда):

```powershell
dotnet run --project C:\Games\Legacy\launcher\src\LegacyLauncher.Tests -c Release
```

Тесты сверяют аргументы сервера и входа со скриптами стенда `Legacy\LegacyBF3\run\` (`start.ps1`, `common.ps1`, `join.ps1`),
правку `Config.lua` (побайтово), хвост логов, разбор ответов бэкенда и занятость портов.

## Запуск

```powershell
C:\Games\Legacy\launcher\src\LegacyLauncher.Gui\bin\Release\net10.0-windows\LegacyLauncher.exe
```

## Локальный сервер и сетевой сервер

**Локальный** (по умолчанию, «Открыть для LAN» выключено). Бэкенд объявляет адрес 127.0.0.1,
сервер виден только этому ПК. Вход на 127.0.0.1:25300 под аккаунтом этого ПК; пароль не нужен.

**Сетевой** (хост включает «Открыть для LAN»). Бэкенд объявляет LAN-IP хоста, а лаунчер хоста
рассылает объявление на UDP 47990. Гость видит сервер в «Серверы → Сеть LAN» и входит с логином
и паролем. Аккаунт гостя создаётся на бэкенде хоста (`POST /accounts/ensure`), клиент идёт на
LAN-IP хоста (`BF3ACT_DNSREDIR_IP`) и на порт игры хоста.

Что нужно для сетевого сервера:

1. Оба ПК в одной подсети, сеть отмечена как «частная» (брандмауэр пропускает правила профиля private).
2. Хост: «Открыть для LAN», запуск сервера, затем «Открыть порты для LAN (UAC)» на вкладке «Настройки».
   Кнопка выполняет `netsh http add urlacl` (HTTP бэкенда на LAN-адрес) и два правила брандмауэра.
   Это нужно один раз; без URL-ACL гости не смогут войти.
3. Гость: в поле LAN-IP ничего не менять (определяется сам), выбрать сервер в «Серверы → Сеть LAN»,
   ввести логин и пароль, нажать «Подключиться».

Ограничение: HTTP бэкенда и пароль идут по LAN открытым текстом. Это стенд для домашней сети, не для интернета.

## Порты

| Порт | Назначение |
| --- | --- |
| 25300 (TCP/UDP) | игровой сервер |
| 8080 (TCP) | HTTP-API бэкенда (аккаунты, список серверов, админка инстанса) |
| 10041 (TCP) | Blaze |
| 42127 (TCP) | редиректор |
| 17554 (UDP) | QoS бэкенда |
| 47900 (TCP) | RCON сервера, только 127.0.0.1 |
| 47990 (UDP) | объявления лаунчеров в LAN |

## Что запускает лаунчер

Бэкенд: `C:\Games\Legacy\LegacyBF3\backend\Legacy.Backend.exe serve ...` с теми же портами и путями,
что в `run\start.ps1`. Сервер: `evbots-loader.exe --dedicated ... -- -serverInstancePath ...`
с переменными `BF3ACT_*` и `EVBOTS_*` из `run\common.ps1` (мост, менеджер и `LIVE_SEARCH` включены).
Вход: `evbots-loader.exe --client ... -requestStateParams ...` с `BF3ACT_DNSREDIR_IP` = адрес хоста, как в `run\join.ps1`.
С 23.10.2026 загрузчик — свой (`EVBots-dev\loader`, имя в `EVBots.Core\Paths.cs`: `LoaderName`); EV Launcher в старой
установке без него берёт `activation-loader.exe` (`Paths.FindLoader`).

Бэкенд и сервер стартуют через `cmd.exe` с выводом в файлы, поэтому остаются работать, даже если
закрыть лаунчер (окно спросит, останавливать ли их). Вход в игру стартует напрямую.

Остановка касается только процессов, которые запустил сам лаунчер. Чужой сервер или чужой бэкенд
лаунчер не трогает, а показывает, что они запущены не лаунчером. Клиент `bf3` лаунчер не закрывает.

## Что пишется в файлы стенда

- `Admin\Startup.txt`: `vars.serverName` и `vars.maxPlayers` (через `POST /admin/startup`).
- `Admin\MapList.txt`: одна строка «карта режим 1» (через `POST /admin/maplist`).
- `Admin\Mods\fun-bots\ext\Shared\Config.lua`: только число `InitNumberOfBots`. Файл меняется побайтово,
  перед записью копия в `logs\config-backup\`. Если значение совпадает, файл не трогается.
- `legacyext.dll` лаунчер не копирует. Деплой DLL остаётся ручным (правило 15: бэкап в `backup\<дата>\`,
  сервер остановить до копирования).

## Логи

Вкладка «Сервер» → «Логи»: «Лаунчер», «Бэкенд», «Сервер (загрузчик)», «legacyext.log (Lua)»,
«Лог игры (RuntimeLog)». Файлы процессов: `logs\backend-*.log`, `logs\server-*.log`, `logs\loader-*.log`.

## Ограничения и что не сделано

- Карта и режим: одна карта в ротации. Выбор карт и режимов вручную, список не проверяется по данным игры.
- Число ботов: задаёт только `InitNumberOfBots` (в balanced_teams значение на команду: 8 дают около 15 ботов).
  Точное число ботов лаунчер не гарантирует.
- Мод fun-bots включить и выключить из лаунчера нельзя. Мод берётся из `Instance\Admin\Mods\fun-bots`.
- Сетевой вход между двумя ПК не проверен на практике: проверены сборка и юнит-проверки ядра.
  Перед показом проверить: объявление на другом ПК, HTTP на LAN-адрес, вход гостя.
- Старт сервера ждёт регистрации в бэкенде до 150 секунд; при ошибке смотрите лог «Сервер (загрузчик)».

## Если что-то не работает

- «Порты заняты»: запущен другой бэкенд или сервер (стенд `LegacyBF3\run`, BF3LegacyLan). Остановите его вручную.
- «Бэкенд не ответил за 25 с»: откройте лог «Бэкенд», там причина (обычно порт или файл).
- «Нет связи с хостом»: проверьте, что хост открыл порты (кнопка на вкладке «Настройки») и один профиль сети.
- «HTTP не отвечает» при проверке LAN: нет URL-ACL, нажмите «Открыть порты для LAN (UAC)» на хосте.
- Сервер не виден в LAN: у хоста не включено «Открыть для LAN» или сервер не зарегистрирован в бэкенде.
