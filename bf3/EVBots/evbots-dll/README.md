# LegacyEXT — аналог VeniceEXT для локального BF3

`legacyext.dll` (x86) — моддинг-интерфейс того же контракта, что у
`veniceext.dll` (Venice Unleashed), но полностью локальный: без Zeus,
без ключей, без интернета. Цель — чтобы VU-совместимые Lua-моды
(`fun-bots` и другие) работали без правок.

## Структура

```
src\
  ModdingInterface.h    контракт: 1 экспорт, vtable 5 методов (сверен с veniceext.dll)
  ModdingInterface.cpp  реализация объекта
  EngineHooks.[h|cpp]   обходники (detour), счётчики, CallOriginal через трамплин
  InlineHook.[h|cpp]    установка/снятие inline-хука: 8 байт атомарно, трамплин
  X86Length.[h|cpp]     декодер длин инструкций x86-32 (сколько байт украсть)
  LegacyLog.cpp         лог в %LOCALAPPDATA%\Legacy\logs\legacyext.log
  LegacyEXT.TestApi.cpp экспорты для самотеста
test\
  LegacyEXT.Test.cpp    32-битный тест-хост: 41 проверка
  X86Length.Dump.cpp    дампер для сверки декодера с capstone
thirdparty\lua-5.4.2\  исходники Lua 5.4.2 (MIT), та же версия, что у VU
build.cmd              сборка: cl.exe x86, /W4 /WX на нашем коде
HOOK-SURFACE.md        поверхность хуков: из потребностей VEXT/fun-bots
```

## Контракт veniceext.dll (сверен статически)

- один экспорт `GetModdingInterface` (RVA 0x007023F0 у настоящей DLL);
- объект ровно 4 байта (одна ссылка на vtable);
- vtable ровно 5 слотов в `.rdata`;
- **slot[0] — НЕ деструктор** ⇒ у `ModdingInterface` нет виртуального
  деструктора, иначе все слоты съедут.

## Inline-хук: как это работает и что выучено

Патч цели: 8 байт одной атомарной операцией — `E9 rel32` на обходник +
3 NOP. Кража пролога: **целое число инструкций суммарно ≥ 8 байт**
(размер патча), границы считает собственный декодер длин (`X86Length`).

Трамплин — правильный порядок, выученный через краш:

```
[украденные инструкции] [E9 rel32 -> target+stolen]
```

Прыжок ПЕРВЫМ — ошибка: украденные байты не выполняются никогда, а
`pop ecx; ret` в теле функции снимает чужой адрес возврата (наблюдали
0xC0000005 по адресу 0x3). Обходник обязан вернуть EAX оригинала.
`Remove()` восстанавливает пролог из сохранённой копии (`original_`),
а не пересборкой.

Отказы — безопасны: если пролог содержит относительные переходы, данные
или VEX/AVX, хук НЕ ставится. Неверно украденная длина хуже отказа.

## Проверки

Самотест (тест-хост ставит 4 хука на свои же функции):

```
cmd /c build.cmd
build\LegacyEXT.Test.exe        :: ИТОГ: успешно 41, провалено 0
```

Консоль кодировки ломает — если нужен вывод в файл:

```
cmd /c "chcp 65001 >nul && build\LegacyEXT.Test.exe > build\out.txt 2>&1"
```

Сверка декодера с capstone (поточечная, критерий: ноль неверных длин):

```
python C:\Games\re\verify_decoder.py build\LegacyEXT.Test.exe
python C:\Games\re\verify_decoder.py build\legacyext.dll
```

Лог DLL накапливается между запусками: перед чистым прогоном удалить
`%LOCALAPPDATA%\Legacy\logs\legacyext.log`. Адреса ASLR-рандомизированы —
сравнивать их между запусками бессмысленно.

## Правила сборки

- всё под x86: bf3.exe 32-битный;
- наш код `/W4 /WX`, исходники Lua — `/W3` с подавлением шумов;
- `build.cmd` чистит `obj\` и `objdump\` перед компиляцией;
- журналы работ: `Legacy\ext\MODLOG.md`.
